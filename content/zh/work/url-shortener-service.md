# URL 縮短網址服務

## 專案概述

這是一個全端短網址服務，讓使用者能夠輕鬆分享連結，同時擁有更高的控制權，管理連結的存取方式與有效期限。

除了基本的短網址生成功能，服務也支援自訂別名、密碼保護及到期日設定，並提供連結管理儀表板，讓使用者能在同一個介面集中管理所有建立的短網址。

本專案的目標是打造一個兼具直覺操作體驗與可靠資料驗證、持久化儲存機制的全端應用程式。

## 系統架構

本專案使用 Nuxt 與 TypeScript 建構，搭配精簡且各司其職的技術，負責使用者介面、資料驗證與資料持久化。

- [**Nuxt**](https://nuxt.com/) + [**Nuxt UI**](https://ui.nuxt.com/)：建構應用程式介面，並透過可重複使用的元件組織全端應用程式。
- [**Zod**](https://zod.dev/)：定義使用者輸入的驗證 Schema，確保資料符合一致的規範。
- [**Prisma**](https://www.prisma.io/) + [**SQLite**](https://www.sqlite.org/)：定義資料模型，並透過關聯式資料庫持久化儲存短網址資料。
- [**Sqids**](https://sqids.org/)：將數字 ID 編碼為精簡且適合用於 URL 的識別碼。

整體架構明確劃分各層的職責：前端介面負責收集使用者輸入、驗證邏輯負責檢查資料、應用程式邏輯處理連結相關操作，而 Prisma 則負責資料庫存取。

## 核心功能與技術決策

### 使用 Sqids 產生精簡 ID

精簡且易於分享的識別碼能讓短網址更加簡潔。Sqids 可以將數字 ID 編碼為適合放入 URL 的字串，避免直接暴露原始數字形式的 ID。

- **技術決策：** 使用 Sqids 取代傳統的遞增式 ID 字串或雜湊字串方案。
- **實作方式：** 不直接暴露資料庫自動遞增的主鍵（例如 `/1`、`/42`），也不需要額外儲存一組字串 slug，而是在需要時即時將主鍵 ID 編碼成精簡的短碼（例如 `/b9Kx2`）。
- **優點：** 保留以資料庫主鍵進行直接查詢的效率，例如透過 `WHERE id = ?` 查找資料，同時維持短網址的簡潔性。Sqids 的字元表與封鎖清單等設定則集中管理於伺服器端的 Runtime Config。

### 安全的重新導向與存取保護中介層

- **中介層處理流程：** 透過 H3 Server Middleware 攔截進入的路由請求，集中處理短網址的驗證與重新導向邏輯。
- **請求驗證：** 使用正規表示式檢查 URL 格式、排除與應用程式保留路由衝突的路徑，並檢查短網址是否已超過有效期限。
- **密碼保護：** 當使用者存取需要密碼的短網址時，系統會將其導向密碼驗證頁面。驗證成功後，透過安全的 HttpOnly Cookie 與授權 Cookie 管理後續存取權限。

### 使用 Zod 進行 Schema 驗證

短網址服務的資料驗證不只是檢查 URL 字串是否合法。自訂別名、密碼及到期日等選項，都帶來額外的驗證需求。

透過 Zod，可以集中定義並重複使用驗證規則，讓不同操作維持一致的資料規範，並在資料寫入資料庫之前，及早拒絕不符合要求的輸入。

### 使用 Prisma 與 SQLite 持久化資料

Prisma 提供具型別支援的資料庫存取介面，以及以 Schema 為基礎的資料模型管理方式。搭配 SQLite，不需要另外維護獨立的資料庫伺服器，就能實現輕量化的資料持久化機制。

這樣的組合簡化了本機開發與部署流程，同時保留關聯式資料模型的彈性，方便未來隨著應用程式成長擴充功能。

### 彈性的連結設定

自訂別名、密碼保護與到期日，分別滿足不同的連結分享需求：

- **自訂別名：** 讓短網址更容易辨識與記憶。
- **密碼保護：** 在使用者取得受保護連結的目標內容之前，增加存取驗證機制。
- **到期日設定：** 讓短網址在指定時間之後停止提供存取。

將這些選項整合在同一個短網址建立流程中，可以在不增加主要操作複雜度的前提下，提供更具彈性的連結管理方式。

## 開發挑戰

### 驗證不同的連結設定

每個選用設定都有各自的限制。例如，自訂別名需要檢查唯一性，到期日需要一致的時間判斷方式，而密碼保護則需要適當的存取控制機制。

透過 Schema 驗證，可以明確定義使用者輸入的規範。不過，對於單靠輸入驗證無法保證的條件，仍需要搭配資料庫約束與伺服器端檢查，確保資料一致性與操作安全性。

### 在使用體驗與存取控制之間取得平衡

一般短網址應該能讓使用者順暢地完成重新導向，但對於受到密碼保護或已經過期的連結，系統則需要採取不同的處理方式。

因此，重新導向流程必須在導向目標網址之前，先確認連結的狀態與存取條件。密碼驗證應由伺服器端執行，而有效期限也必須在實際存取時重新檢查，不能只依賴前端判斷。

### 維持直覺的連結管理體驗

連結管理儀表板需要讓使用者清楚掌握已建立的短網址及其設定。自訂別名、目標網址與到期日等資訊，都會影響使用者辨識與管理連結的方式。

因此，介面設計需要在資訊完整性與操作簡潔性之間取得平衡，讓常用操作容易找到，同時避免過多設定資訊造成介面負擔。

## 專案總結與未來改進

本專案整合了全端應用程式開發、Schema 驗證、資料庫建模與 URL 路由處理等實務，將這些技術應用於一個具體的產品需求。

這個短網址服務不僅提供基本的短網址生成功能，也支援彈性的連結設定、資料持久化與集中式連結管理，建立了後續擴充功能的基礎。

未來可以考慮以下改進方向：

- **流量分析：** 追蹤短網址的點擊次數，提供基本的使用統計與流量分析。
- **強化連結管理：** 隨著連結數量增加，加入搜尋、篩選與分頁功能。
- **強化存取安全性：** 檢視密碼儲存方式，並加入請求頻率限制與濫用防護機制。
- **連結生命週期管理：** 自動清理過期連結，並改善無效或無法存取連結的處理方式。
- **Redis 快取：** 加入快取層，減少重複的資料庫讀取，降低重新導向流程的查詢延遲。
- **測試覆蓋率：** 擴充單元測試與端對端測試，涵蓋短網址建立、重新導向、密碼驗證及有效期限等情境。
